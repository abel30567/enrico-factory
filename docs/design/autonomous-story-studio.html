Architecture proposal · agentic story pipeline

Autonomous Story Studio

A Pixar-style studio run entirely by agents, built for an ongoing show. Part 1 is the story and art room. Part 2 adds production in Unreal Engine, platform editing and distribution to YouTube, TikTok and Instagram. Every stage pairs deterministic checks with judged review, and the audience's response feeds the next episode and the studio's own improvement loops. No human approves anything inside the loop.

Rules of power

With no human director, these rules take the place of the director's authority. Every agent's instructions include them, and the producer enforces them.

  1. No agent approves its own work

    Makers make, judges score, the showrunner decides, the producer enforces.

  2. The charter changes only by amendment

    The showrunner proposes a change and the Braintrust votes on it. Each amendment is logged with its evidence.

  3. Engagement can propose but never lock

    Metrics produce notes and pivot proposals. They never approve a scene.

  4. A revision must beat the old version blind

    Judges compare old and new head to head without knowing which is which. Absolute scores are never enough.

  5. A note raised twice can't be rejected

    If the same problem appears at two screenings in a row, the showrunner has to act on it.

  6. Released canon is never edited

    A mistake in a released episode is fixed in a later episode, never by changing the old one.

  7. The producer's caps always win

    Cost, time and iteration limits override every other agent.

System map

Four rooms, each with its own orchestrator, so no single agent runs the whole show. Work moves left to right as locked packages. Story and distribution also talk to each other directly, and everything the audience does flows back through the analysts.

Part 1

Story and art

The story room from the first version of this proposal. Its output is a locked story reel per episode, which Part 2 turns into finished video.

Story room architecture

There are five layers. Two feedback paths keep it running: notes go back to the showrunner, and released video plus engagement go back to the signal layer for the next round.

Three loops on three clocks

A show evolves because its loops run at different speeds. Fast loops polish scenes. The slow loop changes what the show is about, and only with evidence.

Every proposal states what it touches and a hypothesis written before testing, so it can be judged by whether it worked afterward.

Pivot lab

A cheap branch of the story. Accepted P2 and P3 pivots are built only to animatic quality across the episodes they affect. Each variant runs against the current plan in blind A/B tests with the Braintrust, the audience sim and the held-out judges.

A pivot that wins is adopted and amends the bible. A pivot that loses goes back to the queue with a cooldown and a playbook note saying why. Released episodes are never changed, so the lab only ever affects episodes that haven't shipped.

How the system itself evolves

Series bible

Versioned charter and canon ledger. Every change is an amendment with the vote, the evidence and a link to the hypothesis behind it. Each episode records which bible version it was built from.

Playbook

Lessons learned, each with evidence, a confidence level and an expiry date. For example: "cold opens under 20 seconds retain better," with links to the hypotheses that showed it. Lessons that stop holding up decay out of the playbook.

Judge calibration set

Grows with every release as scenes get labeled by real audience response. This is how audience behavior gradually replaces human taste, without ever handing engagement the power to lock.

Agent instructions as code

Each season the retro agent proposes changes to agent instructions and rubrics. A change is replayed against past episodes and must win against the held-out judges without regressions before it's adopted. Every version is pinned and logged.

Part 2

Production, post and distribution

The locked story reel becomes a finished episode rendered in Unreal Engine, then platform variants, then posts whose results feed the story room. The orchestration follows the Fermi agent-orchestration kit and its content-factory adaptation: makers build, checkers verify, one orchestrator locks, and GitHub holds all state.

Part 2 · room 1 of 4

Production room

Orchestrator: the line producer. Turns the locked story reel into a locked master rendered in Unreal Engine.

Production orchestration

Production gets its own orchestrator, the line producer, so the story showrunner never locks a shot and the line producer never changes the story. Six actors, each with a hard limit.

Line producer

Files shot tickets from the locked reel, launches every worker, rules after three rounds of notes, and is the only role that locks a production stage.

May never build or check.

Makers

One artifact per ticket, on its own branch and worktree, built only from locked assets. Each posts READY, ADDRESSED or BLOCKED and exits.

May never lock, merge or touch another shot.

Lint (factory CLI)

Deterministic checks: same input, same result. Returns PASS, FAIL or ERROR. ERROR means the check couldn't run and is never read as either.

May never make a judgment call.

Checkers

Judged review by an agent that didn't make the work, from a different model family where possible. Notes are Blockers or Issues; only a Blocker stops a lock.

May never fix the work.

Showrunner

Owns the locked reel, bible and canon. Rules on any production question that would change the story, such as cutting a beat that's too costly to render.

May never lock a production stage.

Producer

Stands in for a human owner's greenlight. Spending over budget and anything irreversible, such as a public post, passes its automatic gate.

May never make a creative call.

Production rules

  1. A verdict counts only if it names the head commit and the manifest hash, is newer than the maker's last READY or ADDRESSED, and comes from the stage's named checker.
  2. Stages lock cheapest first. No final render until layout, animation, simulation and lighting are locked on previews.
  3. Makers see only locked assets. A new asset version marks every shot that uses it stale, at that shot's earliest broken stage.
  4. A simulation is locked as a cache, not as solver settings. Renders only read caches.
  5. After three rounds of notes on one ticket, the line producer rules.
  6. Nothing reaches a public feed without a platform gate PASS on the exact file being posted.

Why Unreal instead of video generation

In a 3D engine the scene is data. A character's height, a prop's position, a camera's focal length and the time of day are values you can read, so continuity and physics become tests with right answers. A generated video only gives you pixels, so every check is a judgment call.

The same scene can also be rendered again: from a second camera for a vertical cut, at higher quality for the final, or after one fix without disturbing anything else.

Production room architecture

The same five layers as the story room. The line producer is the only role that locks. The showrunner answers story questions but never locks a shot.

Production loops on three clocks

Shots iterate in hours, sequences in days, and the whole episode in about a week. Only the episode loop hands anything to another room.

Stage ladder

The stages follow Pixar's production pipeline, from story and art through modeling, rigging, sets and cameras, animation, simulation, lighting and rendering. Each shot climbs them in order, and every iteration below the final render runs on fast previews.

Every stage pairs a deterministic lint with a judged check by an agent that didn't do the work. Because the scene is queryable, most continuity and physics questions land in the lint column.

Determinism contract

Unreal is deterministic only under stated conditions, so the contract names them: one pinned engine build, one render-node hardware class, fixed seeds, and Chaos async physics at a constant fixed step with substepping off and Enhanced Determinism on.

Floating-point results can still differ between machines, so the system never relies on simulating twice in production. A locked simulation is stored as a cache, and every render reads the cache. Renders are compared within a perceptual tolerance rather than bit for bit, because temporal effects add noise.

Test levels as evals

Golden scenes run on every engine or asset change, like unit tests:

  • Physics: drop, stack and cloth tests with stored reference caches.
  • Characters: range of motion, walk and run cycles, and the full expression and viseme set.
  • Sets: a color chart plus chrome and grey balls placed in every set, rendered for exposure and color checks.

A change that moves a golden result past tolerance fails the gate, and the diff is attached to the ticket.

Process map: one shot through animation

The same nine steps repeat at every stage. Workers post a marker and exit; nothing starts the next worker except the line producer.

The nine steps

  1. The line producer files a shot ticket from the locked reel: beat IDs, frames, characters, set and cameras.
  2. The animator works in its own worktree from locked assets, renders a preview and posts READY.
  3. Preview frames go to the media store. The pull request commits only their manifest row.
  4. Lint finds 6 cm of foot slide on frames 112–118 and posts FAIL with blocker B1.
  5. The line producer relaunches the animator, which fixes the contact and posts ADDRESSED.
  6. Lint runs on the new head: PASS.
  7. The performance reviewer compares the take with the board and the previous take, blind: APPROVED.
  8. The lock gate confirms every verdict is fresh, names the current head and comes from the named checker. The line producer posts LOCK.
  9. The merge is the lock. The shot's simulation ticket opens.

Markers

State comes from labels and the newest marker on the pull request, never set by hand. Every verdict line names the head commit and manifest hash it reviewed.

Reframe by re-rendering

Layout authors a 9:16 camera for every shot alongside the 16:9 one, so the vertical cut is re-rendered with its own framing instead of cropped. The gate checks that faces, action and captions stay inside each platform's safe zone, which differs because each app puts its buttons in different places. Cropping is only a fallback.

Captions from the script

Captions come from the locked script and the dialogue track, not from speech recognition, so the words are known to be right. Lint checks timing against the audio, characters per line and the safe zone.

CTAs that ask real questions

The CTA writer drafts from the story intent packet. Lint blocks known engagement-bait patterns, such as asking for a single word or emoji in the comments, and requires a comment prompt to ask something about the story.

  • Passes: "Where do you think Pim goes when the tide turns?"
  • Fails: "Comment PIM if you want more!"
  • One CTA per video. A subscribe line appears once, after the hook lands, never in the opening seconds.

Staged release

A public post can't be taken back once people have seen it, so release is staged: private upload, a check that the platform finished processing and kept captions and disclosure, then a scheduled public switch. The producer's gate approves the switch; no human does.

Distribution room

Orchestrator: the channel desk. Publishes gated packages, verifies them live, and turns platform data into notes.

Distribution room architecture

Operators instead of makers: each platform agent holds only its own platform's token, and posts only files with a gate PASS on the exact hash.

Distribution loops on three clocks

A post goes live in hours, is measured over a seven-day window, and feeds the season loop.

The writers' room and the channel desk exchange two structured packets as GitHub issues. Neither side edits the other's work, and both packets are checked before they're used.

Rules for the exchange

  • Theories are signal, not script. When comments predict the plot, writers can satisfy or subvert the theory. The charter decides, and the analyst tracks whether surprises or payoffs hold attention better.
  • Spoiler lint checks every title, caption, thumbnail and CTA against the packet's spoiler list.
  • Beat-level diagnosis runs on YouTube only, because it's the only platform that returns a curve across the video. TikTok and Instagram questions get answered by comparing episodes, never by reposting the same video.

Autoresearch: how the studio improves itself

The researchers and analysts run loops from the Fermi autoresearch skill: change one thing, measure one number, keep the change only if it beats the best result by more than the noise, and log every run. No loop can edit its own metric, harness or judges.

Recursion with a guard

Method researchers read new papers and engine releases and turn them into hypotheses in the experiment queue. The retro agent updates each loop's strategy list from the results log.

A loop never changes its own metric. Changing a metric is a metric amendment, accepted only if the new metric predicts real audience outcomes better than the old one on held-out episodes.

Noise first

Each loop runs 5–10 no-op controls before it starts and sets its keep threshold at two or more times their spread. A candidate that clears it is re-run before it's kept.

Live platform tests are slow and noisy, and each needs a new episode, since reposts lose to originals. So live loops only confirm what offline loops already found.

Autoresearch lab architecture

The lab never changes a room directly. A winning change becomes a pull request that the room's own orchestrator must lock after that room's checks.

Autoresearch loops on three clocks

Experiments run in minutes, programs in days, and metrics change at most once a season.

Trust boundaries, open questions, build order

Trust boundaries

  • Workers reach only their worktree, locked assets (read-only) and their ticket's path in the media store.
  • Only the line producer locks production stages; only the post supervisor locks variants.
  • Only channel agents hold platform tokens, and they post only files with a platform gate PASS on the exact hash.
  • No agent edits its own harness, metric, tests or judges.
  • Credentials live in the environment, never in tickets, prompts or comments.

Open questions

  • Git LFS or Perforce for Unreal's binary assets?
  • Pin one GPU node class for reproducible renders, or accept a perceptual tolerance across classes?
  • Which characters and sets are realistic enough to need AI disclosure on each platform?
  • Who replies to comments, and within what limits?
  • Music licensing that covers all three platforms.
  • Real cost per finished minute. Nothing has been measured.
